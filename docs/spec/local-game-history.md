# Browser-local completed-game history

The My Results page reads retained first-completion submission records from this browser only. It uses the existing record decoder and exact ruleset/date/puzzle key builder. It does not create identities, send submissions, mint attempts, modify games, clear storage, fetch answers, join current Daily to Archive by date, or read other players' records. Browser data is untrusted display data, not competitive authority or proof of a unique human.

The current reader supports the shipped submission:v1 nine-slot Daily/Archive/Classic contract. Classic can finish early; its run score is replayed through the same engine. Points maxima and per-at-bat points use the record's historical ruleset, not today's score settings. The list/details UI consumes the adapter's maximum and at-bat rows and makes no fixed score/length assumption. Unknown future schemas or variable-length contracts are withheld until a versioned reader has their issued length; fact count alone cannot establish length. Custom 1–10 uses its separate signed server ledger and requires an authorized history reader in a later stage.

The existing writer retains its first completed payload through retries, replay and local-game reset. My Results reads that record independently from mutable gameplay saves. A record's pending/submitted/conflict/rejected marker is local metadata; unconfirmed entries are labeled accordingly. Native terminal facts are normalized and scoring is replayed by the engine. Malformed/inconsistent records are omitted with an explicit unreadable notice. Storage denial is unavailable; no record is an empty list, never an invented zero.

Some older games have only gameplay saves, which may represent practice or replays. They are not silently substituted for the original completion. Cleared data, missing completion records and other-device games cannot be recovered from population aggregates or anonymous cookies. Details show recorded initials/outcomes/scores only; full player answers are not reconstructed or requested. React escapes local text and the personal list is not server-rendered or indexed.
