This supplements the existing account-gated launch plan; it does not authorize activation, leagues, H2H, public Discover or large visual redesign. Owner decision: account required to **issue/save/share**; anonymous draft and friend play remain open; official Daily Nine always guest-playable.

## Evidence and ranked execution
1. **QA ownership migration version reconciliation — verified complete:** Compared stored QA `supabase_migrations.schema_migrations.statements[1]` byte-for-byte with committed `20261026233000_add_custom_v2_verified_creator_owner.sql`. Postflight history shows only committed version, no old version; rows unchanged. Production schema NOT migrated. Do not mistake reconciliation of this one version for full parity of earlier QA histories; do not blind `db push`.
2. **Account-aware creator exclusion — P1 pending:** At bootstrap and before result admission, detect a verified account matching the immutable puzzle's owner. Treat same-owner play as preview even on an unmarked second device or after a lost creation response. If an anonymous attempt already exists when creator identity is observed, persist sticky noncompetitive provenance keyed to that attempt so later sign-out cannot restore eligibility. Admission must check provenance atomically with the completed attempt. Preserve legacy marker exclusion, other-account play, anonymous friend play, and scoring. Never trust an account/creator flag in the client.
3. **Real provider QA — P1 blocked on isolated configuration:** Verify Google/Apple/email OTP, PKCE exchange, refreshed session cookies, account switch during preserved draft and parallel requests on protected isolated-QA origin. Each request owns the *verified UUID at that request*. No production flags before proof. Provider continuity policy: different verified emails (Apple private relay vs ordinary email) do not guarantee same account; never merge by email. Either explicitly implement separately proved provider linking, or show a clear original-method limitation before launch; manual account recovery requires a separately approved security design. Same-email auto-linking requires provider QA, not speculation.
4. **Release/migration parity:** Production remains without `creator_account_id`; rehearse idempotence and original-row invariants on isolated QA, then separately plan production application/backout. No broad db push or unguarded migration reapplication. Preserve FK `ON DELETE SET NULL`, owner-capability legacy rows, service-only grants, immutable answers. Validate protected hosted creator→My Creations→guest completion and real iPhone Safari/Android Chrome plus enabled-feature rollback.
5. **Later bounded risk:** Add browser cookie count/eviction/reopen stress test and determine retention requirements before any cookie-storage redesign. Preserve old challenge cookies on migration. My Creations keyset pagination before claiming all-time completeness (currently newest 40); no identity-by-email repair and no speculative account service.

## Next PRODUCT milestone — shared Custom gameplay and completion design

One gameplay implementation and one score/recap implementation for: (a) guest from friend URL, (b) authenticated nonowner, (c) creator preview, and (d) future public Discover entrant. Unlisted is share-link visibility, NOT access control. Contextual attribution, creator name, title, dates, plays, and relevant next actions may differ *when backed by real data*. The result screen shows score/maximum, per-player recap, and genuine comparison when available; no fabricated averages, rankings or ratings. Creator statistics/management live in a separate owner view and never count creator preview as eligible friend completion. Review wireframes and physical mobile flows with owner **before substantial UI implementation**. Publishing may later change visibility metadata only, not the puzzle ID, frozen roster/clues or historical scores. Account-verified future league membership and H2H are deferred, not part of launch.

## Stop conditions

Stop feature activation for missing provider setup or QA credentials, issuer/attempt DB schema mismatch, uncertain owner-exclusion race/provenance, unknown production migrations, no physical-device acceptance or enabled rollback, or any attempt to count creator play competitively. Continue unrelated authorized safety work without weakening release gates.
